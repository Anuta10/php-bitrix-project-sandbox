# Публикация на GitHub и Render

Проект подготовлен так, чтобы код лежал в публичном GitHub-репозитории, а живая PHP-версия автоматически разворачивалась на Render.

## 1. Создать пустой репозиторий на GitHub

Рекомендуемое имя:

`php-bitrix-project-sandbox`

В GitHub при создании репозитория не добавляйте README, `.gitignore` и лицензию — они уже есть в проекте.

## 2. Первый push из VS Code / PowerShell

Из корня проекта:

```powershell
git init
git branch -M main
git add .
git commit -m "Initial project portfolio version"
git remote add origin https://github.com/Anuta10/php-bitrix-project-sandbox.git
git push -u origin main
```

Если GitHub попросит авторизацию, подтверждайте её в браузере. Пароль аккаунта в терминал вводить не нужно.

## 3. Проверить GitHub Actions

После push откройте вкладку **Actions** в репозитории. Workflow `PHP checks` должен завершиться зелёным статусом.

Render настроен на `autoDeployTrigger: checksPass`, поэтому после подключения он будет публиковать изменения только после успешных CI-проверок.

## 4. Подключить Render

1. Войти на Render.
2. Выбрать **New → Blueprint**.
3. Подключить GitHub и выбрать репозиторий `php-bitrix-project-sandbox`.
4. Render найдёт `render.yaml` в корне.
5. Подтвердить создание сервиса.

Для Render используется отдельный `Dockerfile.render`. Локальный `Dockerfile` и `compose.yaml` при этом остаются без изменений.

Сервис слушает порт `10000` и имеет health-check `/health`.

## 5. После первого успешного деплоя

Render выдаст публичный адрес вида:

`https://<имя-сервиса>.onrender.com`

Откройте его в режиме инкогнито и пройдите пункты из `ПРОВЕРКА.md`.

После этого стоит добавить фактическую ссылку Live Demo:

- в верхнюю часть `README.md`;
- в проектные профили и отклики;
- в профиль GitHub (Website);
- при желании в описание репозитория.

## 6. Следующие обновления

После локальных изменений:

```powershell
php tests/run.php
php bin/check.php
git add .
git commit -m "Коротко описать изменение"
git push
```

GitHub Actions проверит проект. Если проверки прошли, Render автоматически задеплоит новую версию.

## Важно про демо-сессии

У проекта нет общей базы данных. Изменения посетителя живут только в его PHP-сессии. При перезапуске контейнера или начале нового календарного дня демо может сброситься — для публичной песочницы это нормальное и ожидаемое поведение.

На бесплатном тарифе Render сервис может останавливаться при отсутствии трафика, поэтому первый заход после простоя иногда занимает дольше обычного.
