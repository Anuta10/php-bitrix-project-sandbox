# Project work / Проектная работа

## Русский

Этот репозиторий используется как интерактивное подтверждение навыков для проектной работы по PHP и 1С-Битрикс.

### Какие задачи подходят

- доработка существующих проектов на PHP / 1С-Битрикс / Bitrix24;
- кастомные компоненты, модули, D7 / ORM, события и агенты;
- API / REST и логика синхронизации данных;
- AJAX, JavaScript, поиск, фильтры, пагинация и динамические интерфейсы;
- внутренние сервисы и корпоративные порталы;
- диагностика ошибок, багфиксы и локальный рефакторинг production-кода.

### Формат

- разовая задача с конкретным результатом;
- отдельный этап проекта;
- проектная работа ориентировочно на 1–6 месяцев;
- фиксированная цена после оценки понятного объёма или почасовая работа, если весь объём нельзя определить заранее.

### Что полезно прислать для первичной оценки

1. Ссылку на проект или краткое описание системы.
2. Что сейчас происходит и что должно происходить после доработки.
3. Скриншоты, ТЗ или пример ожидаемого интерфейса, если они есть.
4. Желаемые сроки.
5. Бюджет или удобный формат оплаты, если он уже определён.

Если проблема не локализована, разумно начать с небольшой диагностики и только после неё фиксировать объём реализации.

## English

This repository is an interactive proof-of-work portfolio for project-based PHP and 1C-Bitrix development.

### Good-fit tasks

- enhancements to existing PHP / 1C-Bitrix / Bitrix24 systems;
- custom components and modules, D7 / ORM, events and agents;
- API / REST and data synchronization logic;
- AJAX, JavaScript, search, filtering, pagination and dynamic interfaces;
- internal tools and corporate portals;
- production bug diagnosis, targeted fixes and local refactoring.

### Working format

- a one-off task with a concrete deliverable;
- a defined project stage;
- project work roughly 1–6 months long;
- fixed price after scoping a clear task, or hourly work when the full scope cannot be known up front.

### Useful details for an initial estimate

1. Project link or a short description of the system.
2. Current behavior and the expected result.
3. Screenshots, specification or reference UI if available.
4. Target timing.
5. Budget range or preferred pricing model, if already defined.

If the issue is not yet localized, a short diagnostic step is usually the safest starting point before committing to implementation scope.
