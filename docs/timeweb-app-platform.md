# Timeweb Cloud App Platform

Эта конфигурация нужна для основного публичного стенда песочницы в Timeweb Cloud.
Render можно оставить как резервный стенд.

## Какие файлы используются

- `docker-compose.yml` — точка входа для App Platform.
- `Dockerfile.timeweb` — production-образ PHP + Apache.
- `docker/apache-timeweb.conf` — Apache-конфигурация для порта `8080`.
- `/health` — маршрут проверки состояния приложения.

Локальная конфигурация `compose.yaml` и Render-конфигурация не меняются.

## Настройка в Timeweb Cloud

1. Открыть **App Platform** и нажать **Создать**.
2. В типе приложения выбрать **Docker → Docker Compose**.
3. Подключить GitHub и выбрать репозиторий `Anuta10/corporate-portal-sandbox`.
4. Выбрать ветку `main`.
5. Оставить включенной сборку по последнему коммиту — это включает автодеплой при новых push в `main`.
6. Выбрать подходящий регион и минимальную конфигурацию для первого запуска.
7. Приватную сеть не подключать: песочница должна быть публичной.
8. Переменные окружения для текущей версии приложения не требуются.
9. Задать понятное имя, например `anna-kolesova-portal`.
10. Запустить деплой.

После запуска проверить:

- `/` — страница портфолио;
- `/demo` — корпоративная песочница;
- `/health` — ответ со статусом `ok`;
- переключение RU / EN;
- создание встречи без «Сопровождения связи» — задача не создается;
- создание встречи с «Сопровождением связи» — появляется связанная задача и маркер;
- дни рождения и события используют текущую дату.

## Домен

На первом этапе достаточно технического домена Timeweb Cloud. После проверки можно подключить собственный домен и использовать его как единственную ссылку в RU и EN резюме.
