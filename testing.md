# Проверка перед публикацией

Короткий список того, что стоит прогнать после любых изменений перед `git push`.

## Автоматически

```powershell
php tests/run.php
php bin/check.php
```

Дополнительно можно проверить синтаксис всех PHP-файлов:

```powershell
Get-ChildItem -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
```

## В браузере

1. Открыть главную `/demo` и проверить мобильную ширину.
2. В «Сотрудниках» проверить букву `М`, поиск `bdfy`, подсветку и «Показать ещё».
3. В «Днях рождения» выбрать период, открыть пример письма и отправить демо-поздравление.
4. В «Календаре» создать обычную встречу без «Сопровождения связи» — задачи быть не должно.
5. Создать встречу с «Сопровождением связи» — возле «Задачи» должен появиться красный маркер.
6. Открыть задачи, затем добавить комментарий к встрече — маркер должен появиться снова.
7. Перенести встречу — обновляется та же задача, без дубля.
8. Открыть «Как работает автоматизация» и отдельно проверить сценарий временной ошибки/retry.
9. Переключить RU/EN и пройти основные страницы ещё раз.
10. Нажать «Сбросить демо» и убедиться, что состояние вернулось к актуальным данным на сегодняшний день.

## Что проверяет `bin/check.php`

- версию PHP;
- обязательные файлы проекта и публикации;
- наличие синтетических сотрудников и группы «Сопровождение связи»;
- отсутствие названий реальных заказчиков в публичном коде;
- отсутствие служебных CSS-суффиксов от промежуточных версий;
- скрытую зарплатную вилку на публичной странице;
- отсутствие заведомо устаревающих названий месяцев в демо-текстах.
